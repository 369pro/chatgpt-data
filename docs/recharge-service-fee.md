# 充值手续费

## 收费规则

充值实付金额不加价，手续费从实付金额中扣除，剩余部分进入对话钱包。聊天仍按模型实际 Token 用量计费，不在聊天时重复收充值手续费。

| 实付金额 | 手续费率 | 手续费 | 净到账 |
| ---: | ---: | ---: | ---: |
| 9.90 | 20% | 1.98 | 7.92 |
| 29.90 | 20% | 5.98 | 23.92 |
| 50.00 | 20% | 10.00 | 40.00 |
| 50.01 | 10% | 5.00 | 45.01 |
| 99.90 | 10% | 9.99 | 89.91 |
| 100.00 | 10% | 10.00 | 90.00 |

单位为 CNY。50 元及以下整单收取 20%，超过 50 元整单收取 10%，不是累进费率，因此 50 元阈值两侧净到账不连续。这是本次产品规则的明确结果。

使用 `BigDecimal`：实付必须是正数、精确到分；手续费按 `实付 × 费率` 四舍五入到分（`HALF_UP`），净到账为实付减手续费。唯一计算入口为 `RechargeQuote.from`。

## 订单与幂等

- `openai_product.price` 是支付金额，`credit_amount` 非空表示钱包商品。接口重新从价格计算报价，避免重复扣费或使用过期净额。
- 新订单保存 `total_amount`（实付）、`product_fee_rate`（费率）、`product_fee_amount`（手续费）和 `product_credit_amount`（净到账）。支付网关验款仍比较实付金额。
- 发货只使用订单的净到账快照，不重新计算手续费。状态 CAS、`balance_grant` 唯一业务键和钱包更新仍在同一事务，重复通知不重复到账也不重复扣费。
- 复用待支付订单时同时匹配支付渠道、价格、净额及手续费快照，避免新购买复用旧报价。
- 手续费上线前的历史订单不追扣，两个手续费字段保持 `NULL`。历史余额订单按原余额快照到账；历史次数订单继续发放次数。
- 收费报表应筛选支付完成订单，再统计手续费快照，不能把未支付订单的手续费当收入。当前不增加独立收入账户或退款功能；后续退款必须使用原订单快照制定规则。

## 接口与页面

商品列表与订单查询返回 `feeRate`、`feeAmount` 和净额 `creditAmount`，前端不自行计算费率。历史订单 `feeRate/feeAmount` 为 `null` 时不补套当前规则。

套餐和付款弹窗展示实付、手续费及净到账；收费规则和手续费说明采用灰色文字，付款前可见。支付金额与钱包净到账不能互换。

## 迁移与验证

先备份数据库，再在 `wallet_purchase.sql` 之后执行 `docs/dev-ops/environment/sql/recharge_fee.sql`，最后发布后端和前端。迁移可重复执行：仅增加缺失列，从商品实付价格计算净额，不更新任何历史订单。

回归入口：`RechargeQuoteTest`、`WalletPurchaseValidationTest`、`WalletPurchaseOrderRepositoryTest`、`WalletPurchaseSqlTest`。真实 MySQL 测试通过 `CHAT_QUOTA_SQL_INTEGRATION=true` 开启，使用独立 fixture 并清理，不触发真实支付。重点覆盖阈值、分位舍入、旧订单、新订单快照、实付校验、并发重复发货和事务回滚。

### 本次验证结果（2026-10-02）

- 后端 21 项测试通过，其中 7 项使用真实 MySQL；29.90 元订单记录手续费 5.98 元，并发与重复发货后钱包仅增加 23.92 元。
- 迁移连续执行两次，当前三档产品净额保持 7.92、23.92、89.91 元，历史订单手续费字段仍为 NULL。
- Java 17 打包通过，后端重启后健康检查返回 HTTP 200；前端 TypeScript 和定向 lint 通过（仅原有 Hook warnings）。
- 浏览器核对套餐及新建订单弹窗：支付 29.90 元、手续费 20% / 5.98 元、净到账 23.92 元，手续费为灰色文字。
- 浏览器没有执行支付宝付款；本次创建的未支付验收订单已关闭。实际余额发放由独立数据库 fixture 验证，不向用户账户注入测试余额。
